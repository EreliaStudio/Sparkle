# PR 08.4b — Model3D::Object et validation visuelle

## Nomenclature et périmètre

- `spk::Model3D::Blueprint` décrit les éléments et leurs points d'attachement ; il est immutable après construction.
- `spk::Model3D::ObjectHeadless` représente la structure instanciée, ses rotations, ses éléments et ses attachements dynamiques ; il dépend uniquement du Core.
- `spk::Model3D::Object<TGraphics>` hérite d'`ObjectHeadless` et gère le cache des vues graphiques et la construction du RenderSnapshot.
- `spk::Model3D::ObjectGraphics<TGraphics>` est un concept C++23, pas une quatrième catégorie de modèle. Il exige `ElementType`, un constructeur depuis `const ElementType&` et `buildRenderSnapshot(builder, transform)`.

Ce changement est un renommage de `spk::Assembly::Blueprint`, `spk::Assembly::Puppet` et `spk::Assembly::RenderablePuppet<TGraphics>`. Aucune fonctionnalité de rendu ou de hiérarchie n'est modifiée.

## Cache graphique

- Le cache reste indexé par `const ObjectHeadless::ElementNode*`, avec vérification de la définition et de l'objet propriétaire.
- `synchronize()` construit ou retire les vues selon la hiérarchie courante ; `buildRenderSnapshot(builder, transform)` synchronise puis contribue aux RenderPass.
- Les vues compatibles sont réutilisées lorsque les articulations bougent. Les copies reconstruisent leur cache ; les déplacements transfèrent les ressources.
- Un échec de construction ou de snapshot ne nettoie pas prématurément le cache. Le `RenderSnapshot::Builder` partiellement rempli doit être abandonné après une exception.

## Validation

Les tests Core couvrent les poses, la hiérarchie, les transformations, les points d'attachement, l'attachement et le détachement d'objets. Les tests Graphics couvrent les caches, la copie, les déplacements et les échecs. Sept captures golden 3D utilisent `ColorVolume`, `ColorView` et `Camera3D`, dont deux poses avec une épée attachée au poignet.

Le renommage déplace les golden images vers `rendering/model3d/` sans altérer les données PNG.

## Suite envisagée — hors périmètre

Une `ViewFactory` globale indexée par type C++ (`std::type_index`) pourra fournir plusieurs types de vues au sein d'un même objet et supprimer le template `TGraphics`. Aucun registre global, auto-enregistrement ni interface View polymorphique n'est introduit par ce renommage.
