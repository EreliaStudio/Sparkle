# PR 08.2 — Fixed Part hierarchy and Skeleton

## Scope

Implement only Core definitions for immutable, shareable hierarchical bodies. No model instance, pose, animation, rendering, mesh, geometry view or equipment attachment is part of PR 08.2.

## Vocabulary (review pending)

- `Part`: concrete extensible body element, possibly without geometry.
- `Part::Attachment`: a named local rigid frame with at most one structural child. The geometric frame can later be reused by instance-level equipment.
- `anchor`: the Part's incoming rigid frame, stored as a matrix.
- `Skeleton`: immutable shared owner of the complete tree and lookup table.
- `Skeleton::Builder`: single-use publishing mechanism.

These names are provisional until the maintainer's terminology review.

## Ownership and construction

The Skeleton owns the root `unique_ptr<Part>`. Each Part owns descendants through `Part::Attachment`. All objects are movable during construction; no deep polymorphic copy is supplied. Both moved existing objects and direct in-place construction are supported, preserving concrete derived types.

The root and descendant Parts can be prepared before entering the Builder, or completed through `builder.root()`. `build()` validates unique Part names, builds a `name -> const Part*` index and publishes `shared_ptr<const Skeleton::Data>` without copying Parts. The Builder is then consumed. Mutations through previously retained construction references after publication violate the immutability contract.

## Geometry

The anchor and each attachment hold a `Matrix4x4` that represents only a rigid position/orientation. Callers configure position with `Vector3` and optional orientation with `Quaternion`. Child anchor and parent attachment frame coincide in the fixed structure.

Future instance transforms and non-inherited per-Part scaling are deliberately excluded.

## Public usage

```cpp
spk::Part arm("leftArm");
arm.addAttachmentPoint("wrist");
arm.attach<spk::Part>("wrist", "leftHand");

spk::Skeleton::Builder builder;
auto &torso = builder.setRoot<spk::Part>("torso");
torso.addAttachmentPoint("shoulder", {1, 2, 0});
torso.attach("shoulder", std::move(arm));

const spk::Skeleton skeleton = builder.build();
const spk::Part &hand = skeleton.part("leftHand");
const spk::Matrix4x4 &shoulder = skeleton.attachmentPoint("torso", "shoulder");
```

## Invariants

- Attachment names are unique within their Part.
- Part names are unique across a Skeleton.
- One structural child maximum per Attachment.
- Attachment names and geometry remain when a structural child is removed.
- Missing attachment, occupied attachment, missing Part, incompatible typed access and duplicate names raise `spk::Exception`.
- A free attachment's `child()` returns `nullptr`.
- `attachments()` is a read-only vector view. Adding an attachment can invalidate existing references unless appropriate capacity was reserved.
- Part has no parent pointer and no InherenceTrait dependency.
