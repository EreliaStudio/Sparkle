# PR 08.3 — Dynamic Assembly instances (Core)

## Scope

Add articulated runtime instances above the immutable `spk::Assembly` from PR 08.2. No graphics, collision, animation timeline or scene/world transform is introduced.

## Public types

- `Assembly::Attachable`: shared behavior for navigation, parent attachment, cached global matrix and recursive invalidation. Its structural parent is internal.
- `Assembly::Instance`: owns the pose and dynamic element tree for one shared `Assembly`; its root transform is the identity and cannot be changed.
- `Assembly::Instance::ElementNode`: runtime occurrence of a static `Assembly::Element`; reads the element's immutable `anchor()` directly.
- `Assembly::Instance::AttachmentNode`: dynamic articulation associated with one static attachment point. Exposed through an alias of `Assembly::AttachmentNode` to avoid incomplete nested-type dependencies in `Attachable`.

`parentAttachment()`, `children()` and `globalTransform()` are accessible through `Attachable`; structural `parent()` is not part of the public API. `children()` is a non-owning collection of direct `Attachable*`; articulations are not nodes in that traversal.

## Transforms

With column vectors, the global transform of an element or bound instance is:

```text
parentElement.globalTransform() * parentAttachment.transform() * localTransform()
```

The root ElementNode is a child of its owning Instance, with the static root anchor as its local transform. The Instance's own local transform is identity. There is no inverse child attachment-point correction.

The fixed anchor and attachment-point transforms are read from the shared Assembly, not duplicated for each Instance. The AttachmentNode stores a rotation matrix and the product `fixedTransform * rotationMatrix`, updating them only when its rotation changes. The articulation position is therefore fixed while its descendants pivot.

`setRotation(Quaternion | Vector3)` replaces the dynamic rotation; `rotate(Quaternion | Vector3)` post-multiplies a local incremental rotation. Euler Vector3 angles are in degrees, as defined by `Quaternion::fromEuler`. Invalid rotations fail before mutating state.

Cached matrices use `spk::CachedData<Matrix4x4>`. Any change to an articulation invalidates the entire owning Instance and all descendants, including dynamically bound instances. Recalculation is lazy.

## Ownership and lifetime

Dynamic nodes are owned by their Instance through `unique_ptr`; attached instances are owned by their AttachmentNode and transferred to the caller by `unbind()`. `bind(const Assembly&)` creates a new instance; `bind(unique_ptr<Instance>)` transfers an existing instance without copying its pose. Rebinding an occupied articulation or a structural attachment that already contains a child is rejected.

Runtime Instance and nodes are intentionally non-copyable and non-movable so references, cache callbacks, and parent pointers remain stable. Independent instances are created from the same cheap-copy Assembly definition.

## Example

```cpp
spk::Assembly::Instance character(characterDefinition);
auto &shoulder = character.attachment("torso", "shoulder");
shoulder.setRotation(spk::Vector3{0, 0, 90});
shoulder.rotate(spk::Quaternion::fromAxisAngle({1, 0, 0}, 20));

auto &grip = character.attachment("hand", "grip");
spk::Assembly::Instance &sword = grip.bind(swordDefinition);
const auto &matrix = sword.root().globalTransform();
std::unique_ptr<spk::Assembly::Instance> detachedSword = grip.unbind();
```

## Validation targets

Unit tests cover shared static matrices, independent pose, joint pivot, local rotation composition, cache invalidation, mixed hierarchy navigation, binding/unbinding without state loss, and invalid operations.
