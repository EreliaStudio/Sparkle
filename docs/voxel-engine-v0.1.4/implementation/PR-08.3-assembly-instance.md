# PR 08.3 — Dynamic Assembly instances (Core)

## Scope

Articulated runtime instances of the immutable `spk::Assembly` from PR 08.2. No graphics, collision, animation timeline, scale or world transform is introduced.

## Public API

- `Assembly::Attachable`: non-owning direct-child traversal, parent attachment, cached global matrix, and downward invalidation; structural parent remains private.
- `Assembly::Instance`: owns a `unique_ptr<Data>` containing the shared static Assembly, its runtime Elements, their index, and all dynamic attachments. Deep-copyable and movable.
- `Assembly::Instance::ElementNode`: references its immutable Assembly Element and its owner's stable Data. Exposes the Element's attachment nodes.
- `Assembly::Instance::AttachmentNode`: public alias of `Assembly::AttachmentNode`. A true nested definition cannot be forward-declared before the Attachable base because of their mutual type dependencies; the alias preserves the approved call-site name without an artificial intermediary.

`Attachable::children()` returns `const std::vector<const Attachable*>&`, exposing read-only direct children: structural ElementNodes first, followed by dynamically bound Instances in insertion order. It does not recurse automatically. Articulations themselves are not Attachable nodes.

`AttachmentNode::attach(const Assembly&)` constructs an instance, `attach(const Instance&)` makes a deep copy, and `attach(Instance&&)` moves an independent instance. All return `Instance&` referring to the newly owned occurrence. References to bound Instances remain stable when new attachments are added, because each is separately allocated. `attachedCount()` returns the number of dynamically attached instances to one point.

`AttachmentNode::detach(Instance&)` selects one of potentially many attached instances and returns a detached Instance **by value**. Its Data and all descendants are moved without reconstructing the tree. A reference to the detached Instance object itself is invalid after detachment, while references/pointers to its internal ElementNodes stay valid for the lifetime of the returned value. Invalid or foreign attachment requests throw `spk::Exception`.

A detached Instance may be moved at constant structural cost. Moving directly from an instance while it is still owned by an attachment is rejected: detach it first. A move into a descendant of the source is also rejected. Moved-from Instances may be destroyed or assigned a new Instance; tree access is invalid until reassignment.

Copy construction and copy assignment deeply duplicate every runtime articulation and attached subtree. Both copies continue to share immutable Assembly definition data. Copying an attached Instance produces an autonomous copy; assigning to an already attached Instance preserves the target's incoming attachment while replacing its pose and descendants. Copies have independent caches.

## Transform conventions

With column vectors:

```text
element.global = parentElement.global * (staticAttachment * dynamicRotation) * staticAnchor
boundInstance.global = parentElement.global * (staticAttachment * dynamicRotation)
```

The root ElementNode of an Instance is its direct child, with the static root anchor as its local transform. An Instance has no independently editable local or world transform. No inverse child attachment correction or dynamic scale exists.

Static matrices are calculated during Assembly construction and referenced directly by instances. AttachmentNodes store the dynamic rotation as a matrix and cache the attachment product `staticAttachment * dynamicRotation`. `setRotation(Quaternion | Vector3)` replaces the rotation; `rotate(Quaternion | Vector3)` post-multiplies a local rotation. Euler Vector3 values are in degrees. Invalid rotations are rejected before mutating state.

The global matrix of each Attachable is a lazily evaluated `CachedData<Matrix4x4>`. A rotation invalidates only direct children using the affected attachment and their respective descendants, including bound Instances. An attach/detach operation invalidates the newly attached/detached subtree. No bulk update pass is introduced.

## Ownership and example

```cpp
spk::Assembly::Instance character(characterAssembly);
auto &shoulder = character.attachment("torso", "shoulder");
shoulder.setRotation(spk::Vector3{0, 0, 45});

auto &grip = character.element("hand").attachment("grip");
spk::Assembly::Instance sword(swordAssembly);
auto &attachedSword = grip.attach(sword);            // independent deep copy
auto &shield = grip.attach(shieldAssembly);           // another owned occurrence
const auto &worldRelative = attachedSword.globalTransform();

spk::Assembly::Instance detached = grip.detach(attachedSword);
auto &rebound = shoulder.attach(std::move(detached)); // transfers dynamic data
```

The word `worldRelative` in the example is a variable name only: the matrix is relative to the top-level Instance, not a scene/world position.
