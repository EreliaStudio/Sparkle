# PR-08.1 — Fondations techniques récupérées

**Branche source :** `impl/v0.1.4/08.1-reusable-foundations` (dérivée de PR-08)

**Branche cible :** `impl/v0.1.4/08-assembly-hierarchy` (PR #49, et non `V0.1.4`)

## Périmètre conservé

- `spk::JSON::Catalog` : chargement atomique des catalogues, conservant les éléments existants en cas d'échec ; tests de doublons et de parsing.
- `spk::Camera3D` : caméra 3D côté Core, projections perspective et orthographique, matrices de vue mises en cache ; tests mathématiques.
- `spk::Voxel::Geometry` : ressource graphique immutable, meshes opaque, translucide et de profondeur, slots de matériaux et vérification de compatibilité de palette. Aucune palette n'est liée directement à Geometry.
- `spk::Voxel::Mesher` : `bake(const Volume&)` renvoie une Geometry ; les volumes restent dans Core ; tests d'occlusion, profondeur, indices et palettes adaptés.

## Hors périmètre (PR-08.2)

`spk::Body`, `spk::Skeleton`, `spk::Model`, `Model::View`, `Skeleton::Part::View`, joints, sections, pièces articulées, synchronisation Core/Graphics, cache par occurrence et attache de sous-modèles. Aucune architecture de remplacement n'est préjugée.

Les transformations de noms `Registry` vers `Collection` ainsi que les changements aux builders voxel sans lien direct avec ce périmètre sont annulés.

## Vérifications attendues

- Compilation Core sans Graphics ; compilation Graphics ; tests Debug et Release sur plateformes supportées.
- Tests `JsonCatalog`, `Camera3D`, `Mesher`, `VoxelPalette` et non-régression des anciennes fonctionnalités voxel.
- L'API `Voxel::Model` est remplacée par `Voxel::Geometry`, pas par le futur `spk::Model`.
- Les golden images de personnages articulés sont reportées à PR-08.2 ; aucun remaillage par frame n'est introduit.

Ne pas fusionner sans validation explicite du propriétaire.
