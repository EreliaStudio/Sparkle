# Contributing to Sparkle

**Begin with the [feature development workflow](feature-workflow.md):** design and validate a GitHub issue, create an implementation branch after approval, deliver source/documentation/tests together, and submit a linked PR for CI and maintainer review.

Read the [coding style](coding-style.md), the [full architectural guidance](../ai-development-guidelines.md), and [building and testing](building-and-testing.md) instructions. The [AI development and code review guide](../ai-development-guidelines.md) is the complete maintainer decision guide for both human and AI contributors; [docs/AGENTS.md](../AGENTS.md) provides additional agent context.

- [Feature workflow](feature-workflow.md)
- [Coding style](coding-style.md)
- [Build and test](building-and-testing.md)
- [CI testing strategy](ci-test-strategy.md)
- [Write and maintain documentation](writing-documentation.md)

Read the relevant public header, implementation and test before changing behavior. Scope changes to agreed responsibilities. Historical implementation plans and review snapshots remain accessible in Git history; they are not the authoritative description of shipped behavior.
